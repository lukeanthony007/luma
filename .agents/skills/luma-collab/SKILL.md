# Collaborate

Collaboration organizes authorized work and integrates real results; it does not automatically mean creating a team. First inspect the request, relevant workspace instructions, evidence, tools, authority, and constraints. Do ordinary coding, research, and retrieval directly when appropriate. Delegate only when a distinct bounded contribution improves the result or independent collaboration is required. Do not add investigator or critic roles by default.

## Define bounded work

Each assignment states its question and purpose; exact scope and approved sources; relevant context and accepted knowledge; method and expected deliverable; limits on edits, tools, access, and external effects; result format; and handoff condition. Give no broader authority than needed. Confirm capabilities before relying on them; a plan, assignment, or available definition is not a completed contribution.

Avoid duplicate work. State dependencies and sequence work only when one result is genuinely needed by another. Keep independently required responsibilities separate: a lead's review cannot be represented as an independent contribution.

## Select participants and a working arrangement

Inspect the workspace's documented specialists and published capabilities before selecting one. A maintained specialist workspace can carry domain knowledge and tools across assignments; a temporary worker needs only the task context. A directory or role file is not a running participant. Use only delegation or inter-session mechanisms actually supplied by the harness. If unavailable, perform permitted work serially or return a handoff for another operator; identify self-review as self-review and preserve unmet independence requirements.

Directory nesting does not grant access, authority or inherited conversation. Give each child its relevant instructions, selected evidence and bounds explicitly. If it further delegates, it must preserve the original purpose, reduce scope and supply the next participant's context and limits; the receiving lead remains responsible for integrating the result. Peers in another directory can collaborate under separately granted access without being organizational children.

Read authorized published knowledge directly when a fact is enough. Delegate a question when it calls for substantive investigation, interpretation or continuing domain responsibility. Do not forward an entire private Wiki, source collection or transcript merely because a participant might find it useful.

Each handoff identifies the question, contributor, examined source revisions/locations, findings, support, inference premises, qualifications, disagreement, unexamined scope and proposed effect on the receiving explanation. For changed files identify exact paths and the revision inspected. Return actual artifacts or proposed amendments rather than an unsupported completion label. Keep one owner for each shared authoritative page; separate output paths or isolated checkouts prevent overlapping writers, and the owner integrates against the latest version. When the work runs as a brief, the return is the run's `HANDOFF.md`: `# Handoff: <run id>` followed by `## Question`, `## Contributor`, `## Sources examined`, `## Findings`, `## Support`, `## Premises`, `## Qualifications`, `## Disagreement`, `## Unexamined scope`, `## Proposed effect` and `## Changed files`, in that order, matching the fields above.

## Integrate actual work

Read the returned artifact and its evidence, not just its status or summary. Map it to the assigned outcome and constraints. Check source scope, support, uncertainty, omissions, unsupported additions, and changed files against the request. Preserve material disagreement and limitations. Accept, revise with basis, contest with evidence, or leave unresolved; never convert silence or failure into agreement or completion.

Integrate accepted contributions into the deliverable and inspect the resulting whole. Ensure conclusions reflect the actual work and reconcile stale or dependent claims. Report which required responsibilities were satisfied by actual work, which failed or remain unavailable, and what integration does not establish. Dispatch alone is never evidence that collaboration succeeded.
